## Why this fixes the user's reported bug

The user reported: *"Profile page shows hardcoded data."*

**Root cause:** `ProfilePage.tsx` (lines 497–907) called `root.querySelector('[data-cm-X]')` for 19 different attributes. The template `10-profile.ts` had **none** of these attributes. Every querySelector returned `null`, so every binding block (`if (nameEl) nameEl.textContent = ...`) was silently skipped. The result: the page rendered with the hardcoded "Alex Rivera" / "@arivera" / "1,280 Reputation" / "18 Days" / etc. that are baked into the template.

**Fix:** Add the 19 `data-cm-*` attributes to the template elements that correspond to each piece of dynamic data. Now `querySelector` returns the elements, the binding code runs, and the page shows the real user data.
